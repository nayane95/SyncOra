# User guide

## Onboarding

Continue with Google. Wait for approval. The Super Admin approves your account, sets your role, and assigns your team. A lead needs both the Admin role and a lead membership. A project must be granted to a team before that team's lead can assign project work.

## Morning

Choose the meeting date and team. Select each member. Read their previous working-day notes, completed work, carry-forward tasks and blockers. Availability comes from approved leave plus the working calendar. Add new tasks or explicitly assign existing ones. Update status inline, or open the task editor for priority, assignment, project/module, due date and blockers. Save a draft while discussing; confirm the plan when ready. Existing tasks keep their IDs. Full-day leave never triggers automatic reassignment.

## During the day

Developers use My tasks. Change task statuses, describe blockers, comment on work, and record unplanned work. Task contributors may also see and update shared tasks. Assignment and privileged metadata remain lead-controlled. Status updates fail with a refresh message if someone changed the task first.

## Daily update

Choose a date, review expected attendance/hours, enter completed and remaining work, blockers, additional work, and notes. Select related tasks to capture their current statuses. Hours describe your whole day, not each task. Save a draft or submit once. Submitted records lock until reviewed. Approved records lock until an authorized different reviewer reopens them for revision.

## Evening

Select a member in Evening standup. Review morning assignments alongside current work. Open the developer's submission to approve it or request a revision with a note. The reviewer must be a different person. A lead may record an update verbally using Record update; the system records who entered it. Full-day approved leave is excluded from missing-update alerts.

## Leave

Request a configured leave type, date range and optional private reason. Half-day leave spans one date. Pending requests do not change availability. Authorized different reviewers approve/reject requests; approved overlapping ranges are rejected. Weekend/holiday dates do not add working leave days. Cancel eligible requests explicitly. Reopen submitted work records before changing leave for those dates.

## Reports

Choose any valid date range and authorized team/developer/project/module/status filters. Exports always include approved work records. One developer/day gives one daily-hours row even when several task snapshots match. Task filtering includes that developer's whole daily hours because task-hour allocation is not collected; it does not pretend those are project-specific hours.

XLSX includes Daily Work Logs, Report Details, Daily Summary, Developer Summary, Team Summary, Leave Summary and Task Breakdown. CSV includes the primary daily sheet only. Formula-like CSV text is escaped.

For WhatsApp choose a date inside the report range and person/team style. The initial preview uses approved records and captured task statuses. Edit intentionally, then copy. Choose one team to save a historical message snapshot. Manual preview edits are saved as written; verify them before sharing. The application does not send messages to WhatsApp.

## Administration

Teams maintains membership history. Projects maintains modules and team access. Account approvals are Super Admin controlled. Settings changes working days, holidays, leave types and optional email domains. Integrations is optional. Audit log is read-only and includes recorder/reviewer actions. Notifications presents current review/revision/leave items; it is not an external push/email service.
